# Автомобили в 1С: экспериментальная реализация (до платформенной проверки)

Этот PR начинается от актуального `main` пользователя. **Не сливайте ранее созданный PR #19**: у справочников марок и моделей в main уже свои UUID метаданных.

## Что добавлено

- Справочник `Автомобили`: `Владелец` (ссылка на `ПользователиПриложения`), `Марка`, `Модель`, `ГодВыпуска`, `VIN`, `ГосНомер`, `ВАрхиве`, `Фото` (ХранилищеЗначения), `ФорматФото`.
- Управляемая форма элемента автомобиля в подсистеме «Автосервис». Фото можно загружать через HTTP API; отдельный интерфейс загрузки фото в форме 1С пока не разработан.
- Проверки записи: корректность марки/модели, наличие владельца, год выпуска, VIN.
- HTTP-сервис `ServiceCarAPI`:
  - `GET /ServiceCar/hs/api/car-brands` → `[{id: <1c-uuid>, name}]`
  - `GET /ServiceCar/hs/api/car-models?brand=<1c-uuid>` → `[{id: <1c-uuid>, name, brand: <1c-uuid>}]`
  - `GET /ServiceCar/hs/api/cars?owner=<1c-user-uuid>` → список
  - `POST /ServiceCar/hs/api/cars` → создание
  - `GET /ServiceCar/hs/api/cars/{id}` → получение
  - `PATCH /ServiceCar/hs/api/cars/{id}` → изменение
  - `DELETE /ServiceCar/hs/api/cars/{id}` → архивирование, без удаления записи
  - `POST /ServiceCar/hs/api/cars/{id}/restore` → восстановление.
- Фото при записи: `photoBase64` и `photoMime` (JPEG/PNG/WebP, максимум 2 МиБ). В ответе `photo` — data URI, либо null.

## ВАЖНО: доступ к API

Все автомобильные HTTP-методы, особенно POST, PATCH, DELETE, должны быть доступны **только сервисной учётной записи 1С** и через закрытую сеть. Публикация с анонимным доступом для этих операций недопустима: можно изменить владельца при создании, и 1С доверяет Django как внешнему контроллеру прав доступа.

Перед проверкой API настройте отдельного пользователя информационной базы для сервиса, Basic Authentication и сетевое ограничение публикации 1С. Django требует `ONEC_API_USER` и `ONEC_API_PASSWORD` для нового автомобильного шлюза.

## Обязательный smoke-test в Конфигураторе 1С 8.5.1

1. Загрузить XML-источники, проверить конфигурацию и BSL (в том числе объект `Автомобили` и HTTP `ServiceCarAPI`), обновить базу.
2. Создать Toyota → Camry и пользователя приложения, затем создать автомобиль. Проверить на форме в 1С, что нельзя выбрать модель другой марки.
3. Сервисным пользователем проверить GET марки/модели, POST автомобиля, PATCH госномера, DELETE/restore, чтение по UUID.
4. Проверить обязательность владельца, некорректные UUID, отсутствие модели, 17 символов VIN и фотографии всех разрешённых форматов.
5. Проверить недоступность HTTP-сервиса без авторизации.
6. После успешной проверки выгрузить новый `1Cv8.cf` **из Конфигуратора**, затем обновить XML-выгрузку в main.

## Ограничения

- Этот код не проверялся платформой 1С; выполнены только проверки структуры файлов/метаданных.
- В 1С нет переноса старых автомобилей из PostgreSQL; миграция на стороне Django требует их очистки или отдельного переноса.
- Владение исторически в Django имело таблицу `CarOwnership`; пока реализован один текущий владелец. Переноса истории владения нет.
- Справочники и автомобили в ответах используют **UUID ссылок 1С**, а не прежние числовые ID Django. Клиент Angular должен быть проверен на поддержку UUID.
- Фото передаётся в data URI. Для больших списков потребуется оптимизация превью/отдельная раздача изображений.

## Порядок включения

**Нельзя** сперва развернуть только Django-PR. Сначала проверьте объекты/методы в 1С, затем на тестовой PostgreSQL примените миграции Django, затем запускайте API и сайт. Старый `1Cv8.cf` не содержит этих изменений.
