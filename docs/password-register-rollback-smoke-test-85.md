# Тест записи хеша в регистр — без сохранения тестового пользователя

После проверки парных функций (ожидаем `PASS. Тип значения: Строка`)
нужно отдельно проверить работу регистра `ПаролиПользователейПриложения` на
платформе **1С 8.5.1.1522**. При этом не менять трёх существующих
пользователей и не вводить настоящие пароли.

**Запускать сначала в тестовой копии информационной базы**, где уже
обновлена конфигурация с новым регистром. Код создаёт временного
пользователя и запись регистра **в транзакции**, читает её и **отменяет
транзакцию даже при успешной проверке**. Не запускать в продакшене, если
резервная копия не проверена или пользователю не понятны последствия.

## Как выполнить

1. Откройте Конфигуратор и создайте внешнюю обработку `ТестРегистраПаролей`
   с управляемой формой, как делали для теста хеширования.
2. Создайте в форме событие `ПриОткрытии`.
3. В модуль формы вставьте **весь код** ниже. Не вставляйте его в
   `МодульУправляемогоПриложения` или HTTP-сервис.
4. Проверьте синтаксис, сохраните `.epf`, откройте файл в режиме
   1С:Предприятие. Тест автоматически запускается при открытии.
5. Результат должен быть `PASS: запись, чтение и проверка хеша работают; тестовая транзакция отменена.`
   Если ошибка — ничего не исправляйте наугад, сохраните только её текст.

```bsl
&НаКлиенте
Процедура ПриОткрытии(Отказ)
    Сообщить(ПроверитьРегистрПаролейНаСервере());
КонецПроцедуры

&НаСервереБезКонтекста
Функция ПроверитьРегистрПаролейНаСервере()

    // Только искусственные данные; настоящий пользователь не затрагивается.
    ТестТелефон = "79990000901";
    ТестПароль = "OneC-Register-Test-Only!2026";

    Если НЕ Справочники.ПользователиПриложения.НайтиПоРеквизиту(
        "Телефон", ТестТелефон).Пустая() Тогда
        Возврат "SKIP: тестовый телефон уже занят; транзакция не начата.";
    КонецЕсли;

    НачатьТранзакцию();
    Попытка
        Пользователь = Справочники.ПользователиПриложения.СоздатьЭлемент();
        Пользователь.Телефон = ТестТелефон;
        Пользователь.Имя = "Тест";
        Пользователь.Активен = Истина;
        Пользователь.Записать();
        Ссылка = Пользователь.Ссылка;

        Хеш = ВычислитьСохраняемоеЗначениеПароляПользователя(ТестПароль);
        Если ТипЗнч(Хеш) <> Тип("Строка") Или ПустаяСтрока(Хеш) Тогда
            ВызватьИсключение "Встроенный метод не вернул строковый хеш.";
        КонецЕсли;

        Набор = РегистрыСведений.ПаролиПользователейПриложения.СоздатьНаборЗаписей();
        Набор.Отбор.Пользователь.Установить(Ссылка);
        Набор.Прочитать();
        Набор.Очистить();
        Запись = Набор.Добавить();
        Запись.Пользователь = Ссылка;
        Запись.СохраняемоеЗначение = Хеш;
        Набор.Записать();

        Проверка = РегистрыСведений.ПаролиПользователейПриложения.СоздатьНаборЗаписей();
        Проверка.Отбор.Пользователь.Установить(Ссылка);
        Проверка.Прочитать();
        Если Проверка.Количество() <> 1 Тогда
            ВызватьИсключение "Регистр не вернул одну запись пользователя.";
        КонецЕсли;

        Для Каждого СтрокаРегистра Из Проверка Цикл
            Если НЕ ПроверитьСоответствиеПароляПользователяСохраняемомуЗначению(
                ТестПароль, СтрокаРегистра.СохраняемоеЗначение) Тогда
                ВызватьИсключение "Правильный тестовый пароль не принят.";
            КонецЕсли;

            Если ПроверитьСоответствиеПароляПользователяСохраняемомуЗначению(
                "Wrong-Register-Test-Only!2026",
                СтрокаРегистра.СохраняемоеЗначение) Тогда
                ВызватьИсключение "Неверный тестовый пароль принят.";
            КонецЕсли;
        КонецЦикла;

        // Намеренный откат: не сохраняем тестовый аккаунт и пароль.
        ОтменитьТранзакцию();
        Возврат "PASS: запись, чтение и проверка хеша работают; тестовая транзакция отменена.";

    Исключение
        ТекстОшибки = ОписаниеОшибки();
        ОтменитьТранзакцию();
        Возврат "FAIL: " + ТекстОшибки + "; тестовая транзакция отменена.";
    КонецПопытки;

КонецФункции
```

**Ограничения теста:** транзакция временно записывает объект и регистр в
тестовой базе, а потом откатывает; сторонние необратимые действия при
записи должны отсутствовать. В текущем модуле объекта
`ПользователиПриложения` проверяются только реквизиты и уникальность,
поэтому тест опирается именно на эту известную реализацию.
Внутреннюю реализацию HTTP-службы (`УстановитьПарольПриложения` и
`ПроверитьПарольПриложения`) этот отдельный тест **не вызывает**: они
пока находятся в модуле HTTP-сервиса и не экспортированы в общий модуль.

## Что будет после PASS

1. Вынести общие функции хеширования, установки и проверки в единый
   серверный модуль 1С с контролем прав.
2. Сделать отдельный ограниченный технической аутентификацией HTTPS
   интерфейс **только для проверки** пароля. Запись/сброс пароля не
   публиковать через прежний анонимный ServiceCarAPI.
3. Сделать безопасную установку новых паролей для трёх существующих
   пользователей (доступна только оператору с подтверждёнными правами
   администратора ИБ; защищённая форма с маскированным вводом).
4. Провести end-to-end тесты новой авторизации на отдельном пользователе;
   только потом переводить регистрацию и парольный вход Django. Старые
   MAX/JWT и `CustomUser` не трогать до предусмотренного перехода.

Официальная документация по двум платформенным методам:
https://its.1c.ru/db/v851doc/bookmark/dev/TI000002120

Не публиковать хеши, не выводить значения паролей в сообщения/журнал.
